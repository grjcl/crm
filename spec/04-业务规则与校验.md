# 04 · 业务规则与校验（横切规则集中定义）

> 本文件是**规则唯一权威**：其它交付物只引用规则 ID，不重复描述。
> 每条规则写成**可被测试执行的句子**（「当 X 时，应 Y」），并标注来源章节。
> 规则 ID 规则：`R-<域>-<序号>`。域：`AUTH / PERM / VAL / SM / SORT / DEDUP / SOFT / LOCK / EDIT / TL / STAT / SEC / ATT / TRACK / AUDIT / OFF`。

## 2. 认证与账号（R-AUTH）

| ID | 规则 | 来源 |
|---|---|---|
| R-AUTH-01 | 登录失败提示统一为「手机号或密码错误」，不得区分「账号不存在」「密码错误」「账号停用」。 | PRD §5.1-3 |
| R-AUTH-02 | 当同一手机号连续 5 次密码错误时，锁定 15 分钟，期间提示「密码错误次数过多，请 15 分钟后再试或联系管理员」；计数在 Redis，成功登录后清零。 | PRD §5.1-4 |
| R-AUTH-03 | access token 有效期 2 小时，refresh token 30 天；已登录用户重开 App 且 refresh 有效时应直接进首页，无需重新登录。 | PRD §5.1-6、§5.3 |
| R-AUTH-04 | 账号停用后，该用户全部 token 立即失效，下一次请求返回 401 + 1002「账号已停用」。 | PRD §5.2 |
| R-AUTH-05 | **密码策略裁决（06 疑点 8）**：本期采用 `6–20 位，同时含字母与数字`（以 PRD §5.1 的登录校验为准），不强制定期更换。§18-1 的「≥8 位」作为二期候选，不在一期校验。理由：登录页已按 6–20 实现并写入验收，改 8 位会让「已有账号（若按 6 位建）无法登录」，且一期内网 10 人场景收益低于一致性成本。 | PRD §5.1 / §18-1 |
| R-AUTH-06 | 管理员重置密码后，生成/指定的临时密码只在响应中返回一次，不落日志、不入审计 diff。 | PRD §5.2 |
| R-AUTH-07 | 忘记密码时 App 只提示「请联系管理员重置密码」，不提供自助找回。 | PRD §5.1-5 |
| R-AUTH-08 | 版本检查：`current < latest` 时非强制弹窗；`current < minSupported` 时强制，只有「去更新」。 | PRD §5.4 |

## 6. 去重与查重（R-DEDUP）

| ID | 规则 | 来源 |
|---|---|---|
| R-DEDUP-01 | 归一化函数：去除中英文括号及其内容 `（…）(…)` → 去除所有空白 → 全角转半角 → 英文字母小写。用于查重与合作商同名判定。 | PRD §6.1「忽略括号/空格」 |
| R-DEDUP-02 | **指纹算法（06 疑点 11）**：`fingerprint = sha256( 归一化(org_name) + '|' + (归一化(phone) 或 '') )`；电话缺失时用空串，此时仅按名称去重（同一名称的不同来源会被视为重复，采到第二条直接跳过）。 | PRD §11.3 |
| R-DEDUP-03 | 采集去重比对范围：`lead_pool`（全状态）、`lead`、`org`（未删）三处；命中任一即**不入池**，记 `channel` 运行日志的 `skipped` 计数。 | PRD §11.3 |
| R-DEDUP-04 | 建档查重：`credit_code` 相同 → 强提示并拒绝保存（3001）；名称相似度 `> 0.9` → 弱提示，不阻止保存。 | PRD §6.7 |
| R-DEDUP-05 | 相似度算法：`pg_trgm` 的 `similarity()`，输入为 R-DEDUP-01 归一化后的名称；阈值 `> 0.9`。lead 与 org 使用同一套归一化与阈值。 | 06 疑点 10 结论 |
| R-DEDUP-06 | 合并功能一期不做：无接口、无入口、页面不出现「合并」。 | PRD §6.7 范围对齐 |
| R-DEDUP-07 | 登记发现时与 org 同名 → 不拒绝，返回 `duplicateOrg` 提示「该企业已存在，是否直接跟进？」。 | PRD §9.2 |
