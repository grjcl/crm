## A. 阻塞项（必须定）

### A1 · 是否新增 `GET /users` 全员列表接口

**问题**：归属销售、协作人多选、合作交接、线索分配、商机负责人，这五处都要「从全员里选一个人」，但 54 个接口里没有任何一个返回用户列表，`/meta/dicts` 也不含用户。

**影响面**：`POST/PUT /partners`（协作人）、`GET /partners/{id}`（展示协作人）、`GET /deals`（负责人）、`POST /partners/transfer`（交接选人）、`POST /pool/{id}/assign`（分配选人）。

- [ ] **A1-1 新增 `GET /users?enabled=true`（推荐）**
  返回 `[{id,name,dept,role}]`，权限为全员可读（销售也需要看同事名字才能选协作人）。
  代价：接口从 54 → 55，已冻结的 `v0.2-contract` 需重出 `openapi.yaml` 并升 `v0.3-contract`。**不影响 16 张表**。

- [ ] **A1-2 不新增，隐藏相关控件**
  一期不显示「协作人」与「选他人做负责人」，负责人恒为当前登录人；交接与分配本就无 UI（走脚本）。
  代价：清单 **2.8「归属与协作人」只交付一半**，验收标准要改成「仅归属销售」；2.8 从必做降级为部分交付，需要你接受。

- [ ] **A1-3 其他方案**：________________________________

> **注意**：A1 选 A1-2 时，B1 的协作人字段仍可加（为二期留），但界面不出现选择器。两者不冲突。

### A2 · 推送一期是否做，资质何时启动

**问题**：三处文档口径不一致——PRD §2.2「除计划提醒外不做推送」、§10.2-7 与 §15 要求一期接 uni-push + 5 家安卓厂商通道 + APNs。xlsx 里也同时写了「一期即接入」和「推送均在二期以后」。

**影响面**：§15 的验收指标「到达率 ≥95%」；§10.2-7 的计划到期提醒；S6b 切片。

- [ ] **A2-1 做，一期只做「计划到期当天 09:00」这一条（推荐）**
  未授权 / 推送失败 → 自动降级为 App 内红点 + 列表标记（PRD §10.2-7 已写明）。
  **需要运维在开工前启动**：5 家安卓厂商通道申请 + APNs 证书。审批周期不可控，晚启动会卡上线验收，但不卡编码。

- [ ] **A2-2 不做推送，只做 App 内红点与列表标记**
  好处：省掉资质与联调。代价：§15 的「到达率 ≥95%」这条验收项必须**删掉**，成功指标里的「提醒」只能靠用户主动打开 App。
  需要你同时接受：§10.2-7 与 §15 作废。

- [ ] **A2-3 做，但只接 APNs + 1 家安卓厂商试点**
  折中方案，到达率无法承诺 95%，验收口径要改。

### B2 · 附件是否支持「微信文件导入」

**问题**：清单 2.5 写「拍照或从相册、微信文件导入」，PRD §6.4 只写「拍照/相册」。

- [ ] **B2-1 不支持，只做拍照 + 相册（推荐）**
  uni-app 各端微信文件导入能力不一致，且要额外权限；一期 PDF 已可从相册选。
- [ ] **B2-2 支持**
  属客户端能力，不改契约，但要加端差异处理与真机验证。

### B3 · 采集池丢弃的线索，日后能否重新采进来

**问题**：`lead_pool.fingerprint` 是唯一索引，丢弃的条目仍占着指纹，同一条永远不会再入池。

- [ ] **B3-1 不能重采，丢弃即永久占位（推荐）**
  简单，且「丢掉的别再来烦我」符合销售直觉。
- [ ] **B3-2 允许重采**
  把唯一索引改成部分索引 `WHERE status <> '已丢弃'`。改法已在 `01` 写好，是 1 行 DDL。代价：丢弃过的企业可能反复出现在待确认池。

### B4 · 密码策略

**问题**：PRD §5.1 写 6–20 位字母+数字，§18 第 1 条建议 ≥8 位。

- [ ] **B4-1 6–20 位，必须同时含字母与数字（推荐）**
  与登录页已有校验、§5.1 验收项一致；不对历史账号做长度拦截，避免初始账号登不进。
- [ ] **B4-2 ≥8 位**
  更安全，但要同步改 §5.1 的字段校验与验收项，且需确认没有已创建的 6–7 位账号。
