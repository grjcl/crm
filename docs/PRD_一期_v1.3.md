## 1. 产品概述

### 1.1 背景

公司做商旅酒店分销：上游对接酒店集团、TMC 与批发商拿房量与协议价，下游卖给 TMC 与商旅分销公司，赚差价与返佣。当前客户与供应商资料散落在 Excel、微信和个人手里，跟进靠记忆，合同到期无人提醒，人员离职客户就流失。

### 1.2 一期目标

**把"人与关系"装进手机**：合作商档案 + 发现（线索）+ 商机 + 跟进 + 下次跟进计划，形成一条能独立跑通的最小闭环。

不做订单、不做结算、不做报表——那些在二、三期。

### 1.3 用户与角色

| 角色 | 人数 | 主要动作 |
|---|---|---|
| 销售（SALES） | 6–8 | 建合作商、记跟进、维护计划、推商机、认领线索 |
| 管理员（ADMIN） | 1–2 | 开账号、管标签、配渠道、看全量数据、做交接 |

> 一期只有这两个角色，**不做自定义权限组合**。

### 1.4 成功指标

上线 4 周后：① 每人每天 ≥1 条跟进入库；② 100% 合作商有下次跟进计划；③ 客户资料不再出现在个人微信/Excel 里。

| 空状态 | 居中 3 行灰字 + 一个主行动按钮 |
| 加载 | 列表首屏骨架屏（3 张卡片），下拉刷新用系统样式 |

### 4.3 通用交互

1. **列表分页**：每页 20，上拉加载更多；后端总数 ≤ 20 时不显示"加载更多"。
2. **下拉刷新**：合作商列表、发现三个视图、跟进时间轴支持。
3. **搜索**：输入 300ms 防抖后请求；匹配 `name` / `short_name`，不区分大小写；无结果展示空状态文案「没有找到相关合作商」。
4. **日期显示**：列表/卡片用 `MM-DD`；详情与接口用 `YYYY-MM-DD`；相对描述「今天 / 明天 / N 天后 / 逾期 N 天」。
5. **键盘**：表单页输入框获得焦点时，页面自动上滚，提交按钮不被键盘遮挡。
6. **返回**：Android 物理返回 = 页面返回箭头；有未保存内容时二次确认。
7. **权限**：接口无权限返回 `403`，客户端统一 toast「没有权限执行该操作」。

### 4.4 文案规范

- 统一称"合作商"，不出现"客户/供应商"两个词（历史数据里的行业字段除外）。
- 统一称"发现"，不再出现"线索"作为页面名（对象可称"线索"，如"认领线索"）。
- 统一称"下次跟进计划"，简称"计划"。
- 数量单位：`1,240` 千分位；金额 `86.2 万`。

## 5. 模块一：登录与账号（1.2 / 1.3 / 1.4 / 1.6）

> 一期**只支持手机号 + 密码登录**。短信验证码登录已明确不做；生物识别在二期评估。

### 5.1 页面：登录

**结构**：Logo + 「商旅分销 CRM」+ 副标题 → 手机号 → 密码 → 「登录」→ 一行小字「忘记密码？」「未开通账号请联系管理员」→ 底部说明「本期仅支持手机号 + 密码登录 / 密码错误 5 次锁定 15 分钟」。

**字段与校验**

| 字段 | 类型 | 规则 | 错误提示 |
|---|---|---|---|
| 手机号 | 数字键盘 | 11 位，`^1[3-9]\d{9}$` | 请输入正确的手机号 |
| 密码 | 密文（可切换显示） | 6–20 位，字母 + 数字 | 请输入密码 |

**交互**

1. 点「登录」→ `POST /auth/login { phone, password }`。
2. 成功 → 存 token → 进合作商列表；失败按错误码提示。
3. **密码错误统一提示「手机号或密码错误」**，不暴露账号是否存在。
4. 同一手机号密码错误 5 次 → 锁定 15 分钟（服务端 Redis 计数），提示「密码错误次数过多，请 15 分钟后再试或联系管理员」。
5. 「忘记密码？」→ toast「请联系管理员重置密码」。
6. 已登录用户打开 App：本地 refresh token 有效则直接进首页。

**验收**

- [ ] 手机号格式校验生效
- [ ] 密码错误提示统一，不泄露账号存在性
- [ ] 连续错误 5 次后锁定 15 分钟
- [ ] 登录成功后杀掉 App 重开不需要再登录（7 天）
- [ ] 「忘记密码」给出明确的人工路径

### 5.2 账号开通与停用（1.3，管理员）

- 一期无"用户管理"界面：由后端管理接口创建账号、设置初始密码（密码入参，服务端 BCrypt 存储）。
- **忘记密码**：管理员调用重置接口生成临时密码，线下告知用户，用户首次登录后建议自行修改。
- 停用账号：该用户全部 token 立即失效（Redis 黑名单），再次请求返回 401「账号已停用」。

### 5.3 登录状态（1.4）

- access token 2 小时，refresh token 30 天，静默续期。
- 手动「退出登录」→ 清本地 token 与缓存 → 回登录页。

### 5.4 版本更新（1.6）

- 启动时调 `GET /meta/version?platform=&current=`。
- `force=false`：弹「发现新版本」→「稍后」/「去更新」。
- `force=true`：只有「去更新」，不可关闭。

| 企业简称 | 否 | 文本 ≤20 | 默认取名称前 4 字 |
| 统一社会信用代码 | 否 | 文本 18 | `^[0-9A-HJ-NPQRTUWXY]{2}\d{6}[0-9A-HJ-NPQRTUWXY]{10}$` |
| 法定代表人 | 否 | 文本 ≤30 | 工商资质用，可留空 |
| 注册资本 | 否 | 文本 ≤30 | 如「5000 万元」，自由文本 |
| 成立时间 | 否 | 日期 | 精度到月 |
| 行业 | 否 | 文本 ≤30 | 如 TMC / 商旅分销 / 酒店集团 / 批发商 |
| 所在城市 | 否 | 文本 ≤20 | 如 上海 / 全国 / 东南亚 |
| 注册地址 | 否 | 文本 ≤120 | |
| 官网 | 否 | 文本 ≤80 | |
| 开票抬头 | 否 | 文本 ≤80 | 默认取企业全称 |
| 纳税人识别号 | 否 | 文本 15–20 | 通常等于统一社会信用代码 |
| 开户银行 | 否 | 文本 ≤60 | |
| 银行账号 | 否 | 文本 ≤30 | 仅数字，脱敏展示 |
| 合作标签 | 是 | 多选 | 来自标签字典，至少 1 个 |
| 合作类型 | 是 | 单选 | TMC / 商旅分销 / 企业客户 / 其他，默认「商旅分销」；用于筛选统计（对应需求 3.2） |
| 产品线 | 否 | 多选 | 协议价 / 包房 / 团体 / 机+酒，仅描述性字段，不联动产品库（对应需求 3.3） |
| 合作分级 | 是 | 单选 | 战略 / 重点 / 普通，默认「重点」 |
| 合作状态 | 是 | 单选 | 潜在 / 试单 / 合作中 / 暂停 / 流失，新建默认「潜在」 |
| 归属销售 | 是 | 用户 | 默认当前登录人 |
| 协作人 | 否 | 多选用户 | |
| 结算联系人 | 否 | 文本 ≤20 | 财务/结算对接人（对应需求 4.4），供应侧常用 |
| 企业简介 | 否 | 文本 ≤200 | |
| 附件 | 否 | 文件 | 图片（jpg/png，原图 ≤10MB，上传前压至 ≤300KB）/ PDF（≤10MB），单档案最多 20 个 |

### 6.2 合作标签（2.2）

- 默认三个：`分销`、`供应`、`其他`；可在「标签管理」增删改。
- 一个合作商可打多个标签（互采互销场景）。
- 标签改名：同步更新所有引用该标签的合作商；校验重名。
- 删除标签：若仍被引用，返回 409 并提示「该标签下还有 N 家合作商，请先移除」。

### 6.3 档案页结构（2.6）

顶部 Hero 卡：分级（实心白底）+ 标签 chip + 企业全称（17.5 bold）+ 「城市 · 行业 · 归属 X · 状态」。
下方 4 个指标（**不含间夜/GMV**）：

| 指标 | 计算 |
|---|---|
| 进行中商机 | 该合作商下 `stage < 4` 的商机数 |
| 本月跟进 | 当月该合作商跟进记录数 |
| 联系人 | 该合作商联系人数 |
| 下次跟进 | 计划日期 `MM-DD`，无计划显示「待补」 |

页签：概览 / 联系人 / 跟进 / 商机。
底部操作条（吸底）：`拨打`（调系统拨号，取主联系人电话）+ `记跟进`。

**概览页签**：基本信息 9 行（含合作标签、合作方式）+ 企业简介 + 附件（缩略 + 拍照上传）+ 最近跟进（最多 2 条）。

### 6.4 附件管理（2.5）

- 入口：概览页「附件」区「+ 拍照上传」。
- 流程：拍照/相册 → **图片**客户端压缩（长边 1600px、≤300KB）→ 调 `POST /files/sts` 拿临时凭证 → 直传 OSS → 回调登记 `attachment`。**PDF 不做压缩**，原文件 ≤10MB 直传。
- 支持预览（图片全屏、PDF 系统预览）、删除（仅上传者或管理员；软删 `deleted_at`，列表不展示）。
- 上传失败保留本地文件，重试 3 次后提示。

### 6.5 搜索与筛选（2.7）

- 入口：合作商列表右上放大镜 → 展开搜索框 + 「取消」。
- 匹配字段：`name`、`short_name`；结果高亮命中片段（二期做，一期高亮可省）。
- 与标签筛选叠加：先标签后关键词。
- 点击「取消」清空关键词并退出搜索态。

### 6.6 归属与协作（2.8）

- 归属人默认=创建人；管理员可改。
- 列表默认显示全部（10 人团队不隔离数据），支持「我的合作商」筛选（二期）。

### 6.7 查重与合并（2.9，可选）

- 保存时后端查重：`credit_code` 相同 → 强提示；名称相似度 > 0.9 → 弱提示。
- 命中时弹层：「已存在相似档案：XXX（归属 Y）」→「继续创建」/「去查看」。
- 合并功能一期不做，仅提供提示。

- 单渠道失败重试 2 次，失败记录 `channel.last_error`，不影响其他渠道。
- 合规：只抓公开信息、保留 `raw_url`、**必须人工认领才入库**。

### 11.4 标签管理（7.4）

- 弹层：3 行标签，每行可直接改名（失焦保存，重名校验），右侧 `×` 删除（至少保留 1 个）。
- 底部输入框 + 「添加」。
- 改名联动：所有引用该标签的合作商同步更新；若当前筛选的是该标签，刷新后跟着改名。

### 11.5 版本与关于（7.5）

版本号、检查更新、隐私政策、数据使用说明（静态）。

### 11.6 验收

- [ ] 渠道 5 个字段可保存并回显
- [ ] 关闭开关后「立即采集」跳过该渠道
- [ ] 采集结果去重（同一企业不重复入池）
- [ ] 标签改名后列表 chip 与卡片标签同步
- [ ] 删除最后一个标签被拒绝

## 13. 接口设计

### 13.1 约定

- 前缀 `/api/v1`，JSON，UTF-8。
- 鉴权：`Authorization: Bearer {accessToken}`。
- 响应：`{ "code": 0, "message": "ok", "data": … }`；业务错误 `code != 0`。

- 时间：`YYYY-MM-DD` / `YYYY-MM-DDTHH:mm:ss+08:00`。
