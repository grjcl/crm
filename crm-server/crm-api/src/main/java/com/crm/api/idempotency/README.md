# Idempotency infrastructure (draft; not yet wired to HTTP)

`@Idempotent` is only a marker, not an interceptor. No existing endpoint is protected by it. The future HTTP adapter must run after authentication and authorization and pass the authenticated user ID, exactly one validated Idempotency-Key, method, full path and query, and exact request body to `IdempotencyService.execute`. It must serialize the HTTP response within the supplied operation and map `INVALID_KEY`, `CONFLICT`, `IN_PROGRESS`, and `STORE_UNAVAILABLE` to agreed API responses. Do not use for multipart, streaming, or async endpoints. The cached response stores status, content type and bytes only, not arbitrary headers. Use this component only on the seven operations listed in R-LOCK-06; other operations remain unchanged. The precise missing-key policy for other writes and error mappings require agreement.

A key is scoped to user, with method/target/body checked for conflicts. Redis SET NX claims without expiry: in-progress and all exceptions remain blocked, because the business transaction may have committed. Completed results expire 24 hours after publication; every returned result, including error results, is cached. Redis errors fail closed. Recovery of an abandoned claim requires investigating the database and a controlled manual process; never delete a claim while its operation might still run. No payloads or keys are logged by this component.

**Unresolved safety blocker:** Redis and PostgreSQL do not share a transaction. A crash or Redis failure after commit and before publication leaves an indeterminate permanent claim; Redis eviction, restart, failover, data loss, or external key deletion may instead lose the claim and permit duplicate writes. 24-hour expiry also permits later reuse. Exactly-once database writes cannot be guaranteed by this component alone. A durable database idempotency record in the same transaction and a recovery protocol (and agreed behavior on failure) are required before claiming AC-INFRA-10 / AC-FOLLOW-07 or deploying it as a guarantee. Claim persistence also requires non-evicting durable Redis; it is not a substitute for transactional storage.
